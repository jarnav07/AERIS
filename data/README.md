# Data

This directory contains data used by the ML Aerofoil Predictor research pipeline. The **canonical training dataset is generated locally with stochastic Kulfan airfoils and XFOIL**. Downloaded or historical datasets are separate experiments and are not part of the canonical training workflow.

## Canonical dataset

The canonical dataset is produced by:

```text
AeroSandbox bundled airfoil geometries
        ↓
Kulfan/CST conversion
        ↓
Mean + covariance of Kulfan parameters
        ↓
Random parent selection
        ↓
Convex weighted combination
        ↓
Covariance perturbation + random scaling
        ↓
New synthetic airfoil
        ↓
Random operating conditions
        ↓
XFOIL
        ↓
Aerodynamic + boundary-layer data
        ↓
Parquet shards
        ↓
training_data.csv
```

The implementation lives in `src/airfoil_ml/training_data_generation.py` and is invoked through `scripts/generate_dataset.py` or the `airfoil-ml generate-training-data` CLI command.

### Geometry generation

AeroSandbox's built-in airfoil database is used **only as the source population for the Kulfan statistical model**. Each source geometry is normalised and converted to Kulfan parameters. The generator then calculates the population mean and covariance.

For each generated case, the sampler:

1. Selects the configured number of parent Kulfan airfoils (three by default).
2. Draws convex random weights whose sum is one.
3. Forms a weighted combination of the parent Kulfan parameters.
4. Adds a multivariate-normal covariance perturbation.
5. Applies a random geometric scale factor.

The resulting geometry is a newly sampled synthetic airfoil rather than an entry copied directly from the source database.

### Operating-condition generation

The default configuration currently uses:

- angle-of-attack grid: `-15, -10, -5, 0, 5, 10, 15` degrees;
- a shared uniform and normal random alpha offset for each sweep;
- `log10(Re)` sampled from a normal distribution with mean `5.5` and standard deviation `1.5`, giving a continuous/log-normal Reynolds distribution;
- Mach number `0` by default;
- `Ncrit` sampled uniformly from `0` to `18`;
- forced transition with an 80% default probability, otherwise a random transition location;
- XFOIL maximum iterations of `200` and a `30` second per-case timeout.

These values are configurable through `TrainingDataConfig` and should be recorded with every research dataset.

## Generated-data layout

```text
data/
├── generated/
│   ├── shards/              # resumable XFOIL result shards
│   ├── training_data.csv    # canonical combined dataset
│   ├── generation_manifest.json
│   └── _failed_cases.jsonl
│
├── processed/               # downstream datasets derived from training data
└── raw/                     # optional historical/source datasets
```

Exact filenames may vary with the generator configuration. The generation manifest is the authoritative record of the configuration and run statistics.

### Sharding and resuming

Large jobs are split into independent Parquet shards. XFOIL workers run independently, and completed valid shards can be reused when generation is resumed. Failed cases are recorded separately rather than being replaced with fabricated aerodynamic values.

After generation, successful shards are combined into the single dataset used by the training pipeline.

## Dataset variables

The generated rows contain:

### Geometry

- Kulfan upper-surface weights
- Kulfan lower-surface weights
- leading-edge weight
- trailing-edge thickness

### Flow and transition conditions

- angle of attack, `alpha`
- Reynolds number, `Re`
- Mach number, `mach`
- critical amplification factor, `n_crit`
- upper transition location, `xtr_upper`
- lower transition location, `xtr_lower`

### Aerodynamic targets

- `CL` — lift coefficient
- `CD` — drag coefficient
- `CM` — pitching-moment coefficient

### Additional solver information

- analysis confidence
- XFOIL transition locations
- upper and lower boundary-layer profiles, including momentum thickness, shape factor and edge velocity ratio at sampled surface locations

The aerodynamic coefficients are generated by XFOIL and are therefore solver reference values, not experimental measurements or CFD labels.

## What is NOT the canonical training source

### UIUC

The canonical stochastic generator **does not download or use the UIUC Airfoil Coordinates Database**. The older acquisition code may remain in the repository for historical/alternative experiments, but it should not be used when producing the main ML training dataset.

### Kanakaero fixed-Re dataset

The Kanakaero dataset is a separate historical external dataset. Its documented aerodynamic data are at a fixed Reynolds number and it does not provide the same target set as the canonical XFOIL generator. It must not be silently concatenated with the canonical multi-condition dataset.

### Older fixed-Re or NACA sweeps

Older generated datasets based on fixed Reynolds-number lists, NACA four-digit parameter sweeps, or hybrid tables are alternative experiments. They are not interchangeable with the canonical stochastic Kulfan dataset.

## Reproducibility

Do not treat a generated CSV as sufficient provenance. A reproducible experiment should retain:

- random seed;
- generator configuration;
- requested number of cases;
- XFOIL version/executable;
- worker count;
- generation manifest;
- failure log;
- code revision/commit.

Generated data are intentionally not required to be committed to Git. This keeps the repository small while making the generation process reproducible from the source code and configuration.

## Generation command

From the repository root:

```bash
uv run python scripts/generate_dataset.py --cases 30000 --workers 8 --resume
```

The equivalent package command is:

```bash
airfoil-ml generate-training-data --cases 30000 --workers 8 --resume
```

The resulting canonical dataset is then the common input for every ML model in the comparison study.
